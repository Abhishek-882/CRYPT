## 3. Adversarial Challenges & Edge-Case Insights

While the planning artifacts are approved, the adversarial review identified **three non-blocking micro-structural edge cases** that subsequent implementation agents (`implementer`) must account for:

### Challenge 1: Leg 1 Partial Fills vs. Leg 2 Minimum Notional Size (Template 1 / Milestone 2.1)
- **Vulnerability**: Template 1 specifies that on a partial limit fill ($q_{\text{exec}} > 0$), Leg 2 must be sized strictly to $q_{\text{exec}}$. If a maker order partially fills for an amount smaller than the destination exchange's minimum order notional (e.g. Binance $5.00 min notional, Bybit $5.00 min notional), Leg 2 will fail with an exchange order rejection (`MIN_NOTIONAL` or `QTY_LESS_THAN_MIN`). This would leave Leg 1 unhedged.
- **Mitigation Directive for Phase 2 Implementer**: Add a check in `makerTakerRouter.ts`:
  $$\text{if } (q_{\text{exec}} \times P_{\text{leg1}} < \text{minNotional}_{\text{leg2}}) \implies \text{immediately market unwind Leg 1 instead of dispatching Leg 2}.$$

### Challenge 2: Dynamic ATR Leverage History Depletion (Template 8 / Milestone 4.1)
- **Vulnerability**: Newly listed perpetuals or intermittent REST rate limits may return insufficient 1-hour candles to calculate a stable 24-period ATR. Defaulting to high leverage under missing data could cause liquidation risk.
- **Mitigation Directive for Phase 4 Implementer**: If candle count is $< 14$ or ATR calculation returns `NaN`, enforce a defensive fallback to the exchange minimum tier (e.g. 3x or 5x), never unconstrained leverage.

### Challenge 3: Hyperliquid Key Custody: Main Key vs. Agent Key (Template 7 / Milestone 3.3)
- **Vulnerability**: Template 7 mentions storing the Arbitrum private key encrypted in the vault. Storing the primary wallet private key on a server exposes all wallet collateral if host security is compromised.
- **Mitigation Directive for Phase 3 Implementer**: Use Hyperliquid’s native **Agent API Key** mechanism (`POST /exchange` with `register_api_key`), creating a dedicated temporary session key with trade-only permissions, keeping the master wallet key offline.
